# RETRO Arcade for EDU 技术选型：做一台「GBC 版牧场物语」

> 目标硬件：ELECFREAKS **RETRO Arcade for Education**（MakeCode Arcade 官方板卡 `hw---stm32f401`）
> 目标产品：类似《星露谷物语》的迷你农场游戏，给孩子的第一台「自己的游戏机」。
> 结论：**MakeCode Arcade + TypeScript**。把范围定在「GBC《牧场物语》」而不是「缩水星露谷」。

> **先确认型号**：ELECFREAKS 有两个容易混淆的产品。
> - **2.4 英寸、320×240、独立机身、编辑器里选 F4** → 本文讨论的 MakeCode Arcade 版。
> - **1.8 英寸、160×128、机身里插 micro:bit V2** → 这是 micro:bit 版，工具链是 MakeCode for micro:bit，不是本文的 F4 流程；内存/屏幕都不同，需要另做方案。
>
> 区分方法：看屏幕尺寸、看有没有 micro:bit 插槽、看编辑器里能不能选到 "F4"。

---

## 0. 一句话结论

这台机器不是「能跑星露谷的小电脑」，而是一台**加强版 Game Boy Color**：

- 逻辑画布 **160×120**、**16 色**、**单声道**
- **96 KB RAM**（MakeCode 链接上限）、**448 KB App 区**
- 但 CPU 是 **100 MHz 的 Cortex-M4**，比 GBC 快一个数量级以上

所以正确的目标是：**用现代工具，做一款 GBC 时代规模的农场游戏**。这个规模已经被《牧场物语 GBC》证明可行；难点不在「能不能做」，而在「怎么在 96 KB 里把循环做顺」。

## 1. 硬件事实（先对齐认知）

| 项目 | 参数 | 对开发的含义 |
|---|---|---|
| 屏幕 | 2.4 英寸，320×240 TFT | 物理 320×240；MakeCode 游戏画布固定 **160×120**，2× 放大 |
| SoC | **STM32F412RE**（Board-ID 实测），100 MHz，512 KB Flash / 256 KB SRAM | MakeCode F4 目标只用 **96 KB RAM / 448 KB App 区** |
| 颜色 | 16 色，4 bit/像素 | 一张 160×120 全屏图 = 9.4 KB |
| 按键 | 十字键 + A/B + Menu + Reset | 够做「移动 + 使用工具 + 打开菜单」 |
| 声音 | 单声道蜂鸣器 | 只能做短音效/单旋律，不要指望多轨 BGM |
| 传感器 | 光敏、陀螺仪、震动马达 | 可做震动反馈、摇晃彩蛋；不要做成核心机制 |
| 电池 | 560 mAh | 适合短会话；游戏节奏也应如此 |
| 编程 | arcade.makecode.com → 选 **F4** → WebUSB 下载 | 浏览器开发，孩子也能上手 |

来源：

- MakeCode 官方硬件列表（明确列出 Retro Arcade for Education 为 `hw---stm32f401`）：<https://arcade.makecode.com/hardware>
- MakeCode「自制 Arcade 硬件」规范（160×120×4bpp ≈ 10 KB、至少 96 KB RAM、512 KB Flash、F4 各型号参数）：<https://arcade.makecode.com/hardware/adding>
- ELECFREAKS 官方 Wiki（2.4 英寸 / 320×240 / 560 mAh / 传感器 / MakeCode 平台）：<https://wiki.elecfreaks.com/en/retroarcade/product-introduction>
- 下载方式（选 F4、WebUSB 配对）：<https://wiki.elecfreaks.com/en/retroarcade/program-download-method>

### 1.1 实机确认：F412，但 MakeCode 只用 96 KB

2026-10-18 插上实机读出的数据（详见 [M0 真机读数](m0-results.md)）：

- Bootloader 报告 **Board-ID: STM32F412-Arcade**；芯片是 **STM32F412RE**（512 KB Flash / **256 KB SRAM** / 100 MHz）。
- 但 MakeCode 的 F4 固件只链接了 **96 KB RAM**（App 初始 SP = `0x20018000`）。
- Bootloader 占 64 KB，App 区 **448 KB**（`0x08010000`–`0x0807FFFF`）。
- 当前示例固件占 **326 KB**，**只剩约 122 KB** 给我们的代码 + 美术 + 音效。

所以：**硬件比 MakeCode 用到的更宽裕，但我们现在按 96 KB RAM / 122 KB 可用 Flash 做设计。**
以后如果真的被 96 KB 卡住，自定义 target / 裸机能解锁 256 KB SRAM——这是后话，不是第一版该做的事。

## 2. 「内存非常小」到底有多小

### 2.1 和 GBC 比，其实宽裕

| | Game Boy Color | RETRO Arcade (MakeCode) |
|---|---|---|
| RAM | 32 KB | **96 KB**（保守） |
| ROM/Flash | 512 KB–1 MB | **448 KB**（App 区，扣掉 64 KB bootloader） |
| CPU | 8 MHz 8-bit | **100 MHz Cortex-M4** |
| 分辨率 | 160×144 | **160×120** |
| 颜色 | 4 色/背景（GBC 56 色） | **16 色** |
| 声音 | 4 通道 | 单声道 |

《牧场物语 GBC》在 32 KB RAM 里塞下了：农场、城镇、商店、4 种作物、季节、NPC、存档。我们的 RAM 是它的 3 倍，CPU 快一个数量级，**缺的不是性能，是「不能乱花」**。

### 2.2 RAM 预算（估算）

| 用途 | 预算 | 说明 |
|---|---:|---|
| Codal/Arcade 运行时 + 堆 + 栈 | 45–55 KB | 最大头；随精灵、图像、临时对象增长 |
| 双显示缓冲（160×120×4bpp ×2） | 18.8 KB | 2 × 9.4 KB |
| 精灵 / 瓦片 / 图像缓存 | 10–15 KB | 玩家 + 24 株作物 + UI 足够 |
| 游戏状态 | 2–3 KB | 地图、地块、背包、存档 |
| 安全余量 | 5–15 KB | 防堆碎片 |
| **合计** | **≤96 KB** | 运行时是变量，必须实测 |

关键结论：**内容资产不是瓶颈，运行时和堆碎片才是。**
24 块地、3 种作物、600 格地图的数据量只有几 KB；真正吃内存的是引擎、双缓冲和每个 sprite 的固定开销。

### 2.3 Flash 预算（实机读数，不是估算）

| 用途 | 数值 | 说明 |
|---|---:|---|
| Bootloader | 64 KB | `0x08000000`–`0x0800FFFF` |
| App 区 | **448 KB** | `0x08010000`–`0x0807FFFF` |
| 当前固件（falling duck） | **326 KB** | 最后一个非 `0xFF` 字节 `0x0806182F` |
| **剩余** | **约 122 KB** | 我们的代码 + 美术 + 音效 |

结论：**我们的全部新增内容必须控制在 ~120 KB 以内。**

按这个预算算一遍：

- 64 格 tileset ≈ 8 KB
- 玩家 8 帧 ≈ 1 KB
- 3 作物 × 3 阶段 ≈ 1.2 KB
- 地块/UI 图标 ≈ 3 KB
- 音效 10 个 ≈ 5–10 KB
- 代码（TS 编译后）≈ 30–50 KB

合计约 **50–75 KB**，留 45–70 KB 余量。**够用，但不能做大量动画帧。**

> 注意：UF2 文件本身固定 1 MB（512 KB 镜像 + 块头），**不能拿文件大小判断 Flash 占用**。要看 App 区最后一个非 `0xFF` 地址。

## 3. 候选技术栈对比

| 方案 | 开发速度 | 内存/性能控制 | 孩子可改 | 风险 | 结论 |
|---|---|---|---|---|---|
| **MakeCode Arcade（TS + Blocks）** | 快 | 中（够用） | **强** | 低 | ✅ **首选** |
| MakeCode + C++ 扩展 | 中 | 高 | 弱 | 中 | 备用（性能瓶颈时） |
| 裸机 C/C++（STM32Cube/LL） | 慢 | **最高** | 无 | 高 | ❌ 现在不做 |
| MicroPython / CircuitPython | 中 | 低 | 中 | 高 | ❌ 不可行 |
| PC 原型（Godot/TIC-80）再移植 | 快 | — | — | 低 | 仅用于验证玩法 |

### 3.1 MakeCode Arcade（推荐）

**是什么**：微软的「幻想游戏机」平台。TypeScript/Blocks 写的游戏，编译成原生 ARM 固件，跑在 STM32F4 上。

**为什么适合**：

- 官方支持这块板，选 F4 就能下载，不用碰底层。
- **TS → C++ → ARM 原生代码**，不是解释执行；100 MHz 跑 160×120 的 2D 农场绰绰有余。
- 自带 sprite、tilemap、碰撞、摄像机、粒子、文字、存档、音效/音乐。
- 同一个项目可以在 **Blocks** 和 **TypeScript** 之间切换；引擎用 TS 写，孩子可以用积木改内容。
- 例子、课程、社区都多，遇到问题容易搜。

**必须接受的限制**：

- 固定 **160×120 / 16 色**，没有自定义调色板、没有 shader。
- 内置字体只有 ASCII，**中文要自己做字模或改用图标 + 英文短词**。
- 单声道，BGM 和音效不能同时叠。
- 没有文件系统/SD 卡（官方资料未提供），持久化只能走 `settings`。
- 运行时占掉相当一部分 RAM/Flash，且版本升级可能变化。
- 在线编辑器依赖网络；本地 CLI/VS Code 可行，但要额外配置。

### 3.2 MakeCode + C++ 扩展（备用）

当某个热点（比如大量作物渲染、寻路、复杂 UI）在 TS 里压不住时，可以写 C++ 扩展，仍然编进同一个固件。

- 优点：保住 MakeCode 的下载/调试链路，只把热点下移。
- 缺点：需要懂 PXT 扩展 API、C++、链接配置；孩子完全改不动。
- 触发条件：**实测**帧率 < 30 或 RAM 不够，而不是「预判会不够」。

### 3.3 裸机 C/C++（现在不做）

能榨出最后一滴性能，但代价是：

- 要自己驱动 ILI9341/ST7789 一类的 8-bit 并口屏、按键矩阵、蜂鸣器、IMU、电池 ADC。
- 显示是 320×240 的 **ILI9341 并口屏**（实测）；全屏 4bpp 单缓冲 38.4 KB、双缓冲 76.8 KB。256 KB SRAM 其实够，但要自己写 FSMC/ILI9341 驱动、UI 和游戏框架。
- 烧录要 SWD/DFU，可能失去 MakeCode 兼容；有变砖风险。
- 3–6 周才有第一个可玩画面，而且孩子无法参与。

**只有在 MakeCode 被实测证伪后才考虑。** 我们的游戏规模（24 块地、3 种作物）大概率用不到。

### 3.4 MicroPython / CircuitPython（不可行）

- 没有现成的板级支持，移植屏幕/按键/音频工作量巨大。
- 即使按 256 KB SRAM 算，解释器 + 堆 + 帧缓冲 + 游戏状态也不宽裕。
- 即使跑起来，帧率和内存都远不如 MakeCode 的原生编译。

### 3.5 PC 原型再移植（不推荐作为主线）

用 TIC-80（240×136、16 色）或 Godot（160×120 窗口）快速验证「种田循环好不好玩」是可行的，但移植到硬件等于写第二遍。**如果要做，只做纸面/数值原型，不要做完整游戏。**

## 4. 推荐方案：MakeCode Arcade + TypeScript

### 4.1 工程结构

MakeCode 会把项目里的 `.ts` 全部编译进去，按模块拆文件即可：

```
game/
├── pxt.json              # 目标：hw---stm32f401
├── main.ts               # 启动、场景、主循环
├── config.ts             # 常量：格子大小、天数、价格
├── data/
│   └── crops.ts          # 作物表（数据驱动）
├── systems/
│   ├── farm.ts           # 地块状态机：空地→锄地→播种→浇水→成熟
│   ├── day.ts            # 睡觉、生长、结算
│   ├── inventory.ts      # 种子/产物/金币
│   ├── shop.ts           # 买种子、卖作物
│   └── save.ts           # settings 序列化
├── ui/
│   └── hud.ts            # 天数、金币、体力、当前种子
└── assets.ts             # 图像/音效常量
```

### 4.2 关键实现决策

| 问题 | 决策 | 原因 |
|---|---|---|
| 地面怎么画 | **tilemap**，不是 80 个 sprite | 省 RAM，摄像机/碰撞现成 |
| 作物怎么画 | 只在有作物的地块创建 sprite，共享 3 张阶段图 | 24 株 × 3 阶段，图只存 3 份 |
| 地块状态 | 固定长度 `number[]`（24 项），索引 = y*6+x | 无对象分配、无碎片 |
| 时间 | **行动点**：每次动作 -1 体力，睡觉进下一天 | 比实时时钟省 CPU，对孩子更友好 |
| 存档 | 一个 hex 字符串写进 `settings` | 只占一个 key，版本化容易 |
| UI | 图标 + 数字 + 少量英文短词 | 规避中文字体 |
| 音效 | 3–5 个短 jingle | 单声道，不抢戏 |

### 4.3 数据驱动：作物表

```ts
// data/crops.ts —— 加作物只改这张表，不改逻辑
export interface CropDef {
    id: number;
    name: string;       // 英文短名，UI 用
    days: number;       // 浇水后长几天
    seedCost: number;
    sell: number;
    stages: Image[];    // 3 张：幼苗 / 成长 / 成熟
}

export const CROPS: CropDef[] = [
    { id: 1, name: "TURNIP", days: 2, seedCost: 10, sell: 25, stages: [...] },
    { id: 2, name: "POTATO", days: 3, seedCost: 15, sell: 40, stages: [...] },
    { id: 3, name: "PUMPKIN", days: 4, seedCost: 20, sell: 60, stages: [...] },
];
```

### 4.4 开发与版本管理

1. **浏览器**：<https://arcade.makecode.com/>，新建项目，硬件选 **F4**，模拟器里迭代。
2. **真机**：USB 连接 → 设备配对 → 下载。第一次先烧「Hello World + 按键测试」。
3. **版本管理**：MakeCode 支持 GitHub 同步；或本地用 MakeCode CLI / VS Code 扩展，把 `game/` 纳入 git。
4. **美术**：MakeCode 的 16 色是固定的；在 Aseprite/Piskel 里建一个同色板，只从里面取色，按 160×120 作画 → PNG → 编辑器导入/资产包；量大时写脚本转成 `img\`...\`` 字面量。
5. **素材版权**：不要直接用《星露谷》的图；分辨率、色板、风格都不匹配，而且有版权问题。

## 5. 把「星露谷」压进 96 KB：约束 → 对策

| 约束 | 影响 | 对策 |
|---|---|---|
| 160×120，10×7.5 个 16px 瓦片 | 一屏只能看到一小块农场 | 农场 30×20 瓦片（3 屏宽），摄像机跟随 |
| 16 色 | 画不出星露谷的丰富光影 | 先定 16 色色板；用明度分层，不靠渐变 |
| 中文无字体 | 菜单/对话不能用中文 | 图标 + 英文短词；或做 12×12 汉字字模（30 字 ≈ 2 KB） |
| 单声道 | 不能 BGM + 音效叠加 | 只做短 jingle + 动作音效；菜单音乐单独播 |
| 无文件系统 | 不能存多存档/大地图 | `settings` + 位压缩；一张地图、一个存档位 |
| 运行时吃 RAM | 精灵一多就崩 | 地面用 tilemap；作物按需创建；对象池；压测 24 株 |
| Flash 只剩 ~122 KB | 大动画帧放不下 | 复用瓦片；每个作物 3 帧；音效短 |

### 5.1 地图与镜头

- 农场 **30×20 瓦片** = 480×320 px = 3 屏宽 × 2.67 屏高。
- 可耕种区 **6×4 = 24 格**，其余是装饰（树、石头、房子、出货箱）。
- 摄像机跟随玩家；UI 用 `SpriteFlag.RelativeToCamera` 固定在屏幕上。

### 5.2 一天的循环（无实时时钟）

```
起床（体力 20）
  → 走到地块，按 A（按地块状态决定动作）：
      空地           → 锄地（-1 体力）
      已锄           → 播种（消耗 1 包种子，-1 体力）
      已播种、未浇水  → 浇水（-1 体力，标记 watered）
      已浇水         → 无事发生（或提示）
      成熟           → 收获（+1 产物，-1 体力）
  → 去商店：卖产物 / 买种子
  → 回床边按 A：睡觉
      → 所有 watered 且未成熟的作物 stage +1
      → 清空 watered
      → day +1，体力回满，自动存档
```

没有「几点钟」的压力，只有体力和天数。对 8 岁以下更友好，也省掉一套时钟 UI。

### 5.3 存档格式（约 30–40 字节）

```
byte 0      version
byte 1      day
byte 2..3   coins (uint16)
byte 4      energy
byte 5..7   seed counts ×3
byte 8..10  produce counts ×3
byte 11..34 24 个地块状态，每格 1 字节：
              bit 0      已锄
              bit 1      已浇水
              bit 2..3   作物 id（0–3）
              bit 4..5   生长阶段（0–3）
              bit 6..7   保留
```

序列化成 hex 字符串，`settings.writeString("save", hex)`。回读时按 version 兼容旧档。

> 注意：`settings` 的具体容量上限没有公开的精确数字，按「几百字节到 1 KB」设计；M0 用真机读写一次确认。

## 6. MVP：第一个可玩版本

### 6.1 范围

| 模块 | MVP | 之后再加 |
|---|---|---|
| 地图 | 1 个农场（30×20） | 城镇、商店内部、矿洞 |
| 地块 | 24 格 | 温室、扩张 |
| 作物 | 3 种（2/3/4 天） | 6–8 种、季节 |
| 工具 | 锄头、水壶、种子、收获 | 斧头、钓鱼竿 |
| 经济 | 买种子 / 卖作物 | 出货箱、订单 |
| 时间 | 体力 + 天数 | 季节、天气 |
| 存档 | 睡觉自动存，开机续玩 | 多存档 |
| 目标 | 7 天赚 100G | 还债、解锁新区域 |
| 美术 | 占位瓦片 + 1 个角色 + 3 作物 | 完整 tileset、NPC、动画 |
| 音频 | 4 个音效 | 菜单音乐、环境音 |

### 6.2 验收标准

- 真机稳定 30 FPS，24 株作物 + 玩家同屏。
- 冷启动到可操作 < 2 秒。
- 断电后存档不丢，能续玩。
- 连续过 7 个游戏日不崩溃、不重启。
- App 区末尾 < `0x0807F000`；新增内容 < 120 KB（UF2 文件固定 1 MB，不能看文件大小）。
- 孩子能在 5 分钟内学会「锄地→播种→浇水→睡觉→收获」。

### 6.3 为什么这个范围合理

- 24 株作物 = 最多 24 个作物精灵（每株只显示当前阶段，不叠加 3 张图）；RAM 安全。
- 3 种作物已经能产生「规划—等待—收获」的核心乐趣；第 4 种开始是内容工作，不是技术验证。
- 一屏农场 + 商店就能闭环，不需要城镇/ NPC 也能玩 20–30 分钟。

## 8. 风险与预案

| 风险 | 概率 | 影响 | 预案 |
|---|---|---|---|
| Flash 超限 | 中 | 无法烧录 | 先测空项目；砍动画帧/音效，复用瓦片 |
| RAM 碎片/崩溃 | 中 | 玩到一半重启 | 固定数组、对象池、避免每帧 new；压测 24 株 |
| 中文 UI | 高 | 孩子看不懂 | 图标优先；关键 30 字做字模；英文用短词 |
| 帧率不够 | 低 | 手感差 | 地面 tilemap；作物按需渲染；热点再考虑 C++ 扩展 |
| 工具链/网络 | 中 | 无法编译 | 本地代理；MakeCode CLI/VS Code；离线缓存 |
| 变砖 | 低 | 设备报废 | 不刷非 MakeCode 固件；保留 bootloader；需要时再上 SWD |
| 实机型号差异 | 低 | 内存/屏幕驱动不同 | M0 在真机记录；不依赖未验证的 RAM |
